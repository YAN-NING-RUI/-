## 一、MPU、内存映射与 Cache

### 1. MPU 负责什么？

**MPU（Memory Protection Unit）是内存属性与权限配置单元，不是缓存本身。** 它可按地址区间配置：

- **访问权限**：禁止访问、只读、读写，及相关特权级限制；
- **执行权限**：是否禁止从该区域取指（XN，Execute Never）；
- **内存属性**：Normal/Device 等类型，以及缓存、缓冲、共享属性；
- **区域匹配**：区域基地址、大小、子区域掩码、优先级。

**D-Cache/I-Cache 是硬件缓存；MPU 只影响内存访问是否按可缓存等属性处理。** 有效使用 D-Cache 还需要处理器启用对应缓存，并且目标地址属于可缓存的访问路径。

### 2. `Number`、`BaseAddress`、`Size`、`SubRegionDisable`

| 字段 | 作用 | 易混点 |
|---|---|---|
| `Number` | MPU 硬件区域槽位编号（Region Number） | **不是物理地址**；同一编号重新配置会覆盖原配置 |
| `BaseAddress` | 当前 Region 的地址起点 | 不负责搬移数据，只是地址匹配规则 |
| `Size` | 当前 Region 覆盖区间大小 | 常规 MPU 区域大小须为允许的 2 的幂，基地址按区域大小对齐 |
| `SubRegionDisable` | 按位关闭该 Region 的部分子区域 | **关闭子区域 ≠ 禁止访问该子区域** |

STM32H743 Cortex-M7 MPU 支持 16 个 Region（0～15）。Region 可以不连续编号；**有地址重叠时，编号大的有效 Region 优先**。

例如：

```c
MPU_InitStruct.Number      = MPU_REGION_NUMBER1;
MPU_InitStruct.BaseAddress = 0x24000000U;
MPU_InitStruct.Size        = MPU_REGION_SIZE_512KB;
```

表示用 **Region 1** 描述 `0x24000000～0x2407FFFF` 的 AXI SRAM 地址区间，不代表 CPU 已开启 D-Cache。

> **纠正一处旧示例**：`MPU_REGION_SIZE_288KB` 不是合法的标准 MPU 区域大小宏。D2 SRAM 虽可合计约 288 KB，但不能用单个 288 KB Region 直接配置；应按合法大小拆分/子区域规划。

### 3. 4 GB Region + `0x87` 的实际含义

此前代码：

```c
MPU_InitStruct.Number           = MPU_REGION_NUMBER0;
MPU_InitStruct.BaseAddress      = 0x00000000U;
MPU_InitStruct.Size             = MPU_REGION_SIZE_4GB;
MPU_InitStruct.SubRegionDisable = 0x87;
MPU_InitStruct.AccessPermission = MPU_REGION_NO_ACCESS;
MPU_InitStruct.DisableExec      = MPU_INSTRUCTION_ACCESS_DISABLE;
```

4 GB / 8 = 512 MB，每个 bit 对应一个子区域；`0x87 = 0b10000111`。

- **bit = 1**：该子区域不参与 **Region 0** 的匹配；对应子区域 **0、1、2、7**。
- **bit = 0**：该子区域由 **Region 0** 生效；对应子区域 **3、4、5、6**。

因此 Region 0 的 `NO_ACCESS` 作用于 **`0x60000000～0xDFFFFFFF`**，除非更高编号的有效 Region 覆盖了它。`0x00000000～0x5FFFFFFF` 以及 `0xE0000000～0xFFFFFFFF` 不受 Region 0 这些属性约束。

`HAL_MPU_Enable(MPU_PRIVILEGED_DEFAULT)` 允许**特权级**访问未被有效 Region 覆盖的地址时采用处理器默认内存映射；它**不意味着**未覆盖区域自动可缓存、可缓冲。非特权级访问还须单独考虑权限。

### 4. SRAM、TCM 与 D-Cache

| 存储器 | 典型起始地址 | 数据缓存关系 |
|---|---|---|
| ITCM | `0x00000000` | 紧耦合指令存储路径，不通过普通 D-Cache |
| DTCM | `0x20000000` | 紧耦合数据存储路径，不通过 D-Cache |
| AXI SRAM | `0x24000000` | 可按 Normal Memory 属性使用 D-Cache |
| D2 SRAM | `0x30000000` | 可按适当属性使用 D-Cache |
| D3 SRAM | `0x38000000` | 可按适当属性使用 D-Cache |

**Region 0 不覆盖某块 RAM，只表示它不施加 Region 0 的约束；不是“自动开启缓存”。**

### 5. MPU 与 MMIO、`volatile`、DMA 的关系

- **MMIO**：外设寄存器映射进 CPU 地址空间，由地址译码决定访问到哪一个外设；不是 MPU 创造的。
- **MPU**：为 MMIO 地址配置合适的访问权限及 Device 等内存属性。**Normal Non-cacheable 和 Device 不是同一概念**。
- **`volatile`**：约束编译器对相应对象访问的优化；**不会关闭 D-Cache，也不负责 DMA Cache 一致性**。
- **DMA**：若 DMA 与 CPU 共享可缓存 SRAM，须考虑 Cache Clean/Invalidate、缓存行对齐，或把共享缓冲区配置为合适的 Non-cacheable 区域。

**记忆链：地址决定访问目标 → MPU 决定访问属性与权限 → Cache 根据有效属性参与访问；`volatile` 则是编译器层面的约束。**

## 二、CMSIS-RTOS2 线程相关类型

### 1. `osThreadAttr_t` 与 `osThreadId_t`

| 类型 | 本质 | 何时用 |
|---|---|---|
| `osThreadAttr_t` | 结构体类型 | **创建任务前**描述名称、优先级、栈大小等属性 |
| `osThreadId_t` | 线程标识符类型（CMSIS-RTOS2 常定义为 `void *`） | **创建任务后**保存句柄，供线程管理 API 使用 |
| `osThread_t` | 非 CMSIS-RTOS2 公共标准类型名 | 若在工程中出现，须检查该工程自己的定义 |

```c
static void StartCanTask(void *argument)
{
    (void)argument;
    for (;;) {
        osDelay(10);
    }
}

const osThreadAttr_t canAttr = {
    .name       = "CanTask",
    .stack_size = 1024,
    .priority   = osPriorityNormal,
};

osThreadId_t canHandle = osThreadNew(StartCanTask, NULL, &canAttr);
```

`osThreadNew()` 的核心参数顺序是：**入口函数指针、传给入口函数的参数、线程属性**。`osThreadId_t` 是句柄，不等于任务控制块本体；具体内部表示依赖 RTOS 适配层。

### 2. 线程参数和局部数组不是一回事

```c
void StartCanTask(void *argument)
{
    uint8_t startupData[8] = {0x53U, 0x32U, 0x41U, 0, 0, 0, 0, 0};
    (void)argument;
    // startupData 可以正常使用
}
```

- `argument`：由创建线程时传入的**函数参数**。
- `startupData`：在函数内部创建的**局部数组**；通常位于该任务栈，实际实现可受优化影响。
- `(void)argument;`：表示有意不使用该参数，常用于避免 `unused parameter` 警告。它可以放在函数作用域中的合适位置，习惯上放在开头；**不会限制声明其他变量**。
- 若通过 `argument` 传入指针，指向的数据应在任务使用期间保持有效。

## 三、C 语言：`void`、指针和函数指针

### 1. 分清三种写法

```c
void *p;           // 声明“通用对象指针”变量 p
(void *)somePtr;   // 把表达式转换为 void*，不代表释放或清零
(void)argument;    // 把表达式转换为 void，丢弃结果
```

`void *` 可以承载不同**对象**类型的地址，但不能直接解引用；使用前须转换为合适的目标对象指针类型。`void *` 不是通用的**函数指针**类型。

```c
int x = 100;
void *p = &x;
int value = *(int *)p;
```

### 2. `(void)函数调用()` 仍会执行函数

```c
(void)S2_Transmit(S2_ID_REPLY, startupData);
```

- `S2_Transmit(...)` **正常执行**；
- `(void)` 仅表示**忽略返回值**。

若函数返回 `HAL_StatusTypeDef`，关键通信建议检查返回码：

```c
HAL_StatusTypeDef st = S2_Transmit(S2_ID_REPLY, startupData);
if (st != HAL_OK) {
    // 处理提交发送失败
}
```

**HAL_OK 通常表示提交发送请求成功，不等于总线已实际发送完成。**

### 3. 函数指针变量 vs 函数指针类型

```c
int Add(int a, int b) { return a + b; }

int (*pFunc)(int, int) = Add;  // 函数指针变量
int result = pFunc(3, 5);     // 间接调用；结果为 8

typedef void (*osThreadFunc_t)(void *argument); // 定义函数指针“类型”
osThreadFunc_t entry = StartCanTask;            // 用该类型声明函数指针变量
```

必须区分：

```c
int (*pFunc)(int, int); // 指向“返回 int 的函数”的指针
int *pFunc(int, int);   // 一个“返回 int* 的函数”声明
```

### 4. 为什么不全用直接函数调用？

函数指针的价值在**运行时选择、解耦、回调、统一接口**，而不是保证更快：

- **任务入口**：`osThreadNew(StartCanTask, ...)` 通过统一接口接受不同任务函数。
- **回调**：驱动保存用户处理函数地址，在事件到来时调用。
- **命令分发表/状态机**：按命令选择相应处理函数。

少量固定分支用 `if/switch` 往往更直观；函数指针调用也可能妨碍内联优化。注意函数签名匹配、指针初始化、回调执行上下文与并发安全。

## 四、FDCAN：过滤器索引与发送报文头

### 1. `FilterIndex` 是过滤规则编号，不是 CAN ID 或 FIFO 元素下标

```c
filter.IdType       = FDCAN_STANDARD_ID;
filter.FilterIndex  = 0U;
filter.FilterType   = FDCAN_FILTER_MASK;
filter.FilterConfig = FDCAN_FILTER_TO_RXFIFO0;
filter.FilterID1    = S2_ID_REQUEST;
filter.FilterID2    = 0x7FFU;
filter.RxBufferIndex    = 0U;
filter.IsCalibrationMsg = 0U;
```

- `FilterIndex = 0`：选择标准 ID 过滤器列表中的**第 0 条规则**；其合法范围受 `StdFiltersNbr` 限制。
- `FilterID1`：掩码模式下的目标 ID。
- `FilterID2 = 0x7FF`：11 位均需匹配，实现标准 ID **精确匹配**。
- `FilterConfig = FDCAN_FILTER_TO_RXFIFO0`：匹配的报文进入 FIFO0，**不是 FIFO0 第 0 个元素**。
- 当前 FIFO 路由模式下，`RxBufferIndex` 不是 FIFO 内部元素位置。
- 同一个 `FilterIndex` 再次配置会**替换**该位置规则，而不是追加规则。

掩码匹配条件：

```text
(receivedId & mask) == (filterId & mask)
```

如需**只接收指定 ID**，还要配置全局过滤器拒绝未匹配的数据帧；否则未匹配帧仍可能按全局规则进入 FIFO。

### 2. Tx Header：当前配置是 Classic CAN 标准数据帧

```c
txHeader.Identifier          = id;
txHeader.IdType              = FDCAN_STANDARD_ID;
txHeader.TxFrameType         = FDCAN_DATA_FRAME;
txHeader.DataLength          = FDCAN_DLC_BYTES_8;
txHeader.ErrorStateIndicator = FDCAN_ESI_ACTIVE;
txHeader.BitRateSwitch       = FDCAN_BRS_OFF;
txHeader.FDFormat            = FDCAN_CLASSIC_CAN;
txHeader.TxEventFifoControl  = FDCAN_NO_TX_EVENTS;
txHeader.MessageMarker       = 0U;
```

| 字段 | 核心含义 |
|---|---|
| `Identifier` + `IdType` | 发送的 11 位标准 CAN ID |
| `TxFrameType` | 数据帧而非远程帧 |
| `DataLength` | DLC 编码；此处为 8 字节，**不是随意填整数 8** |
| `ErrorStateIndicator` | CAN FD 的 ESI 信息；Classic CAN 帧不包含 ESI 位 |
| `BitRateSwitch` | CAN FD 数据阶段是否切换位速率；Classic CAN 不涉及 BRS |
| `FDFormat` | 当前为 Classic CAN，整帧使用 Nominal 位时序 |
| `TxEventFifoControl` | 不生成 Tx Event FIFO 记录 |
| `MessageMarker` | 事件关联标记；未启用 Tx Event FIFO 时可为 0 |

`HAL_FDCAN_AddMessageToTxFifoQ()` 将报文提交到发送 FIFO/Queue，并由硬件后续仲裁发送。**提交成功（HAL_OK）与物理总线发送成功是两个不同事件。**

## 五、工程上最值得记住的 8 条

1. **MPU Region Number 是槽位号；BaseAddress + Size 才决定地址范围。**
2. **`SubRegionDisable = 1` 是“该 Region 不生效”，不是“禁止访问”。**
3. **不受某个 MPU Region 限制 ≠ 自动开启 Cache。**
4. **ITCM/DTCM 不通过普通 D-Cache；AXI/D2/D3 SRAM 需按内存属性和 Cache 配置分析。**
5. **MMIO、MPU、`volatile`、Cache 分属不同层次，不能互相替代。**
6. **`osThreadAttr_t` 是创建参数；`osThreadId_t` 是任务句柄。**
7. **`(void)argument` 忽略参数；`(void)func()` 忽略返回值，但函数仍执行。**
8. **函数指针用于动态分发/回调；FDCAN `FilterIndex` 是过滤规则编号，发送 HAL_OK 不等于总线发送完成。**

> **适用性与置信度**：以上为 STM32H743 / Cortex-M7 / CMSIS-RTOS2 / 标准 C 的常规机制，概念层面置信度高。具体工程中还应以当前芯片 RM、编译选项、HAL/CMSIS 版本及实际 Cache/MPU 初始化顺序为准。
