# 从存储层级看 volatile：Cortex-M7 上一个 C 变量的落脚之处

按 Cortex-M7 的视角，一个 C 变量可能落脚的地方可以展开成从内到外的四层阶梯：**CPU 片上通用寄存器、TCM、片上 SRAM、外设寄存器**。（M3/M4 没有 TCM，这一层是 M7 才引入的；M3/M4 上对应的是 F4 的 CCM，M7 换成了 ITCM/DTCM。）

最内层的通用寄存器没有地址，只能由指令编码寄存器编号访问，1 拍完成，而且容量极小：R0~R12 里扣除调用约定和临时值的占用，真正能长期驻留变量的只有 8~12 个，即 32~48 字节（理论天花板 13×4 = 52 字节；带 FPU 再加 S0~S31 共 128 字节浮点）。这是编译器唯一能“免费”缓存变量的地方，也是后面所有问题的起点。

第二层 TCM 在 M7 上直连内核、与内核同频、0 等待，绕过总线矩阵，也不参与 Cache，所以它的访问延迟和寄存器一样确定（1 拍），容量却大得多（几十到几百 KB）。ITCM 供取指，用来放中断向量表和热函数；DTCM 供数据，用来放栈和控制环变量。它的短板是需要软件显式放置（链接脚本、section 属性），而且 DMA 通常够不到——这既是限制（不能当 DMA 缓冲区），也是优点（编译器可以放心假设没有外部写者）。

第三层片上 SRAM 经过总线矩阵，可被 Cache、DMA 可达，是变量的“默认家”。第四层外设寄存器挂在 APB/AHB 上，要穿过总线桥、跨时钟域同步和时钟分频（例如 STM32F407 上 APB1 只有 42MHz 而内核跑 168MHz），单次访问要 6~15 拍，比 SRAM 的 1~2 拍慢一个数量级——慢的原因不在“存储”，而在“路径长”。

除通用寄存器外，其余三层共享同一个 4GB 统一编址空间，只是地址段不同（ITCM `0x0000_0000`、DTCM `0x2000_0000`、AXI SRAM `0x2400_0000`、外设 `0x4000_0000`、内核私有外设 `0xE000_0000`），访问时由总线矩阵按地址译码把请求路由到不同目标。所以“地址能通”并不代表“背后是同一种东西”。

在这条阶梯里还有一层容易被忽略的硬件自动缓存：**M7 的 L1 Cache**（I-Cache / D-Cache，各 0~64KB 可配，32 字节一行，命中 1~2 拍、miss 几十到上百拍）。它和 TCM 是两种不同的不确定性策略：Cache 用“大概率命中”换平均性能，覆盖所有标记为 cacheable 的区域，包括外部 SDRAM 和 QSPI 映射区——那是 TCM 根本救不了的地方；TCM 用“绝对命中”换可预测性，但只管自己那一段地址。吞吐交给 Cache，硬实时交给 TCM，两者在 M7 上可以并存，因为它们在地址空间和物理通路上本来就是分开的。

关于外设寄存器算 ROM 还是 RAM：**都不是**。它不是存储阵列，而是由触发器、锁存器和组合逻辑构成的电路接口，每个 bit 背后直接连着真实的硬件功能（GPIO 的 ODR 位接到引脚输出驱动器，IDR 位接到引脚输入触发器）。它可读可写，这一点像 RAM；但它存的是硬件状态而不是数据，掉电即失效，读回的值也不一定等于写进去的值（写 1 清零、只读状态位、硬件自行修改），所以不属于存储器范畴。真正的 ROM 是 Flash，位于另一个地址段。

C 程序里定义一个变量时，编译器会按自己的模型推断它的行为：中断服务函数不在任何可见的调用图上，编译器无法建模它会在哪一刻插进主流程，也看不出有外部写者；因此它默认“没有外部力量在我不知情的时候改这块内存”，只要寄存器里还有空位，就把这个变量的值驻留进 CPU 片上寄存器反复复用，甚至把整个读操作优化掉。这个优化的合法性建立在两个前提上：**寄存器装得下**（容量只有约 50 字节，装不下就 spill 回栈），以及**没有不可见的写者**。前者靠寄存器分配解决，后者只能靠 `volatile` 解决。

`volatile` 就是把这项推断权收回来：它声明该对象可能以编译器不知道的方式被修改，因此禁止编译器把变量缓存进 CPU 片上寄存器，强制每次访问都回到可寻址存储（SRAM 或 MMIO 寄存器）真正走一次 load/store。具体落到三条约束上：**次数**上每次访问必须真实发生一次（禁掉死代码消除、写合并、读外提）；**取值**上每次读必须重新取（禁掉公共子表达式消除和寄存器驻留）；**顺序**上 volatile 访问之间不得重排。代价也随之量化：这个变量被永久排除在那 50 字节的候选池之外，每次访问都要付一次真实访存——对 SRAM 是 1~2 拍，对一个 APB 外设就是 6~15 拍，这才是“非必要不加 `volatile`”的实账。

需要补充的是边界：`volatile` 只约束“访问次数与取值的独立性”，它**不提供原子性**（`volatile uint64_t` 在 32 位核上仍是两次 load，会撕裂）、**不生成内存屏障**（不保证跨对象顺序，也不保证硬件写缓冲排空）、**不绕过 D-Cache**（DMA 改了 SRAM，你仍可能读到旧 line）——这三件事要分别靠原子操作、`__DMB/__DSB` 和 Cache 维护（clean/invalidate 或 MPU 配 non-cacheable）来解决。所以判断标准最终落回一句话：**要不要 `volatile`，取决于这个地址背后有谁可能写它**——DTCM 里的变量因为 DMA 够不到，通常不需要；外设寄存器因为硬件自身会改，必须加，还要配屏障；DMA 缓冲区不仅要加，还要额外处理 Cache 一致性。
