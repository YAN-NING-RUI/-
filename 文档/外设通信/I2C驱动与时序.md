# I²C 驱动与时序

以 STM32F103 为例，比较硬件与软件 I²C、轮询与异步传输。原始项目记录来自《freertos系统的一些总结.md》。

## 驱动方式选择

| 实现方式 | 调用任务如何等待 | 适用场景 |
| --- | --- | --- |
| GPIO 软件 I²C，轮询或延时 | 调用任务在传输结束前保持在函数中，期间仍可能被更高优先级任务抢占 | 短事务、低频访问、便于直接观察时序 |
| 硬件 I²C，HAL 轮询 | I²C 外设生成时序，调用任务轮询状态，等待完成或超时 | 初始化和简单调试 |
| 硬件 I²C，中断或 DMA | 启动传输后可继续执行，或阻塞在任务通知上等待完成。示例 API 为 `HAL_I2C_Mem_Write_IT` 和 `HAL_I2C_Mem_Write_DMA` | 希望减少忙等，或让其他任务并行处理 |
| 软件 I²C，定时器驱动状态机 | 定时器事件驱动状态推进，SDA 方向、ACK 和总线条件由状态机处理 | 缺少可用硬件 I²C，且能验证中断延迟和完整时序 |

在 FreeRTOS 中，轮询和忙等占用**调用任务的执行时间**。能否切换到其他任务取决于调度策略、任务优先级，以及是否处在关中断或调度被暂停的区间。中断与 DMA 的取舍要看事务长度、触发频率和驱动复杂度。原记录针对手头 F1 项目倾向软件方案，遇到硬件 I²C 异常时，应先按具体型号、硅片修订版和复现条件核对 ST 勘误。

### 软件 I²C 的时序边界

- 普通 I²C 的 SCL、SDA 使用开漏或开集电极加上拉。上拉阻值依据总线电容、允许的上升时间和器件灌电流选取，4.7 kΩ 是常见起点。
- 正常数据位在 SCL 低电平时更新 SDA，在 SCL 高电平时保持稳定。START 和 STOP 通过 SCL 为高时的 SDA 跳变表示。
- 100 kHz 对应 10 µs 周期。高低各 5 µs 是理想 50% 占空比的例子。设计还须满足所用速率模式的最小高低时间、建立保持时间与上升时间。
- 定时器可以提供节拍。完整状态机还需处理 START、重复 START、STOP、ACK/NACK，按设备要求处理时钟拉伸。若目标设备能拉低 SCL，释放 SCL 后应读取实际电平，再推进高电平阶段。
