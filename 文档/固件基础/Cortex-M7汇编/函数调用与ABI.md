# Cortex-M7 函数调用与 ABI

以 AAPCS32 的整数调用为例，追踪参数、返回值和寄存器保存义务。掌握 [Thumb-2 指令与寻址](./Thumb-2指令与寻址.md) 和 [栈与异常入栈](./栈与异常入栈.md) 后，可在反汇编窗口逐条检查函数。

## R0–R15 在调用中的分工 {#core-registers}

| 寄存器 | 典型职责 | 返回后的保留规则 |
| --- | --- | --- |
| **R0** | 第 1 个整数/指针参数；常见的 32 位返回值 | Caller-saved |
| **R1** | 第 2 个参数；部分 64 位返回值使用 R0 与 R1 | Caller-saved |
| **R2** | 第 3 个参数、临时值 | Caller-saved |
| **R3** | 第 4 个参数、临时值 | Caller-saved |
| **R4～R8** | 保存调用后仍然需要的通用数据 | Callee-saved |
| **R9** | 平台约定用途，或额外的被调用者保存通用寄存器 | 平台相关 |
| **R10～R11** | 被调用者保存寄存器；R11 在某些工具链中也作帧指针 | Callee-saved |
| **R12** | 临时寄存器（IP），也用于链接器辅助代码 | Caller-saved |
| **R13 / SP** | 当前栈指针，指向当前栈顶 | 调用边界应按约定恢复 |
| **R14 / LR** | 链接寄存器：普通调用的返回位置；异常时具有其他特殊含义 | 调用其他函数可能覆盖 LR |
| **R15 / PC** | 程序计数器：控制执行位置 | 专用程序控制寄存器 |

### R0～R3：传参和返回值

```c
int add(int a, int b) { return a + b; }
```

典型的高度简化汇编：

```asm
add:
    ADD R0, R0, R1    @ 输入 a 通常在 R0，b 在 R1；结果写回 R0
    BX  LR            @ 返回调用者
```

对于普通 32 位整数参数，前四个一般按 R0～R3 传递；剩余参数通常使用栈。实际还受参数类型、对齐、结构体、浮点 ABI 等因素影响。

### R4～R11 的寄存器分配

这些寄存器**没有硬件固定的业务含义**。编译器可以把循环计数、指针、中间数据放入它们。它们之所以特别，是因为通用函数调用规范要求被调用函数保留其中大部分寄存器的原值；只要要修改，就需要在返回前恢复。

除 R0–R15 外，还可在调试器中观察 xPSR、PRIMASK、BASEPRI、FAULTMASK 和 CONTROL 等特殊寄存器。浮点参数和返回值的位置取决于工具链选择的浮点调用约定。

## BL、LR 与函数返回 {#call-return}

```asm
A:
    BL B          @ LR 被设置为返回到 A 中下一条执行位置
    @ B 返回后继续执行

B:
    ADD R0, R0, #1
    BX LR         @ 返回 A
```

如果 B 自己还会执行 `BL C`，新的 `BL` 会覆盖 B 当前的 LR，因此 B 通常要先保存其返回 A 所需的 LR，或以其他正确方式安排控制流。

## 调用者与被调用者的保存规则 {#register-saving}

设函数 A 调用函数 B：

| 类型 | 寄存器 | 谁保证旧值在 B 返回后还可用？ | B 是否可修改？ |
| --- | --- | --- | --- |
| **Caller-saved**（调用者保存） | R0～R3、R12 | **A**：如果要保留，A 自己想办法保存 | B 可以直接修改，通常不需要还原旧值 |
| **Callee-saved**（被调用者保存） | R4～R8、R10、R11 | **B**：若 B 使用并修改，必须在返回前恢复 | B 可以修改，但返回时这些寄存器须保持符合约定的原值 |
| **平台相关** | R9 | 由具体 ABI 的平台约定决定 | 依约定，不能脱离目标 ABI 一概而论 |

### 调用者负责保留仍要使用的值

- 并不是 A 每次调用前都要 `PUSH {R0}`。
- 只有 A 在调用后**还需要旧值**时，才有保存的必要。
- B 往往把函数参数放在 R0～R3 中接收，并把返回值放在 R0（或 ABI 指定的位置），自然会覆盖原值。

例如：

```c
int B(int x) { return x + 1; }
```

```asm
B:
    ADD R0, R0, #1    @ R0 输入 x，返回 x+1
    BX  LR
```

这不需要保存 R0，因为 B 的契约本来就是把结果返回在 R0。

### 被调用者恢复自己改过的受保护寄存器

如果 B 想修改 R4：

```asm
B:
    PUSH {R4, LR}
    MOV  R4, R0
    @ ...使用 R4 进行计算...
    POP  {R4, PC}
```

B 必须使调用者能继续使用调用前的 R4。如果 B 从不改动 R4，就不必为了“形式上遵守规范”而压栈。

### R9 的例外性

在 AAPCS32 中，R9 可由平台指定为：

- `SB`（Static Base，静态基址）；
- `TR`（Thread Register，线程相关寄存器）；
- 或在不需要特殊职责的平台上作为另一个 callee-saved 通用寄存器。

手写汇编或移植 RTOS 时，按实际工具链和平台 ABI 核对 R9 的角色。

### LR 的保存原因与 R4 不同

```asm
B:
    PUSH {R4, LR}
    MOV  R4, R0
    BL   C
    POP  {R4, PC}
```

- 保存 **R4**：因为 B 需要使用它，却必须向调用者保证它不变。
- 保存 **LR**：因为 `BL C` 会覆盖 LR，B 还需要原先“返回 A”的位置。
- 恢复到 **PC**：是把之前保存在栈中的返回地址用于分支返回，而不是“PC 也属于普通被调用者保存寄存器”。

AAPCS32 要求 SP 始终至少按 4 字节对齐，公开调用边界按 8 字节对齐。检查手写序言时，可以将压栈字节数和局部空间相加，核对调用点和返回时的 SP。

## 同时保留旧 R0 和返回值 {#r0-result}

**结论：如果调用者既要旧 R0，又要被调用函数返回的 R0，就必须在恢复旧 R0 之前先保存/使用返回值。** 被调用函数执行 `BX LR` 后，只是返回到调用者的下一条指令，并不会自动触发 `POP {R0}`。

### 两个值都要保留的完整教学例子

假设 A 内部需要保留旧值 100，同时调用 `B(10)` 得到 11，最后计算 100 + 11 = 111 作为 A 的返回值。

```asm
A:
    PUSH {R4, LR}       @ A 保存 R4 和自己的返回地址，8 字节
    MOV  R0, #100       @ 模拟 A 原本想保留的 R0 值
    PUSH {R0, R1}       @ 保存旧 R0；R1 只是示例用额外保存，保持 8B 对齐

    MOV  R0, #10        @ B 的参数写入 R0，覆盖 R0 原值
    BL   B              @ 返回时 R0 = 11
    MOV  R4, R0         @ 先把返回值 11 转存到 R4
    POP  {R0, R1}       @ 再恢复 A 原本的 R0 = 100
    ADD  R0, R0, R4     @ R0 = 100 + 11 = 111，作为 A 的返回值

    POP  {R4, PC}       @ 恢复调用 A 之前的 R4，按旧 LR 返回

B:
    ADD  R0, R0, #1     @ B(10) 的返回值 = 11
    BX   LR
```

步骤追踪：

| 时刻 | R0 | R4（A 内的临时用途） | 栈里保存的旧 R0 |
| --- | ---: | ---: | ---: |
| A 写入旧数据 | 100 | 未指定 | 尚未保存 |
| A 执行 `PUSH {R0, R1}` | 100 | 未指定 | 100 |
| A 为 B 传参 | 10 | 未指定 | 100 |
| B 返回 | **11** | 未指定 | 100 |
| `MOV R4, R0` | 11 | **11** | 100 |
| `POP {R0, R1}` | **100** | 11 | 已恢复 |
| `ADD R0, R0, R4` | **111** | 11 | 已恢复 |

本例是为解释保存顺序而构造的自洽、可理解的汇编流程；不代表编译器必须按此方式实现 C 代码。R1 的保存并非 ABI 强制，只是便于保持该示例的 8 字节调用栈对齐。

### 只使用被调用函数的返回值

```c
int B(int x) { return x + 1; }
int A(void) { return B(10) * 2; }
```

调用 B 后，A 只需要结果 11，而不需要进入 B 前 R0 的旧值，因此可以直接利用返回值：

```asm
    MOV R0, #10
    BL  B           @ B 返回 R0 = 11
    LSL R0, R0, #1  @ R0 = 22
```

这一段仅展示相关部分；完整非叶子函数还必须正确处理 A 自己的返回地址与栈对齐。

### 编译器常采用更经济的方案

如果某个值要跨多次函数调用长期保留，编译器可能直接把它放入 R4～R11 这类 callee-saved 寄存器，减少每次调用前后反复保存 R0 的次数。

**区分三个动作**：

1. **B 写返回值到 R0**：这是 ABI 的返回值约定。
2. **`BX LR` 返回 A**：只是恢复控制流，不会自行替 A 恢复旧 R0。
3. **A 的后续指令**：决定先使用/转存返回值，还是恢复旧值，或根本不用恢复。

## 用反汇编自查

1. 单步越过 `BL`，确认入参和返回值位于预期寄存器。
2. 记录调用前后 SP、LR 和被调用者保存寄存器，核对函数是否恢复原值。
3. 复现 100 与 11 相加的示例，依次追踪 R0、R4 和栈中的旧 R0。
