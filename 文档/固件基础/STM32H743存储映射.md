# STM32H743 存储映射

从 CPU 发出一条访存指令，到目标内存或外设响应，中间可能经过 TCM 接口、L1 Cache 和总线互连。本篇以 STM32H743VIT6 为例说明地址与访问路径。

## 一次访问经过哪里

| 位置 | CPU 如何访问 | 工程含义 |
| --- | --- | --- |
| CPU 通用寄存器 | 指令编码寄存器编号，例如 `r0` | 编译器可把临时值保存在寄存器中，取舍受寄存器分配和调用约定影响 |
| ITCM / DTCM | 使用映射地址，经专用 TCM 接口 | 常用 ITCM 放热点代码，DTCM 放栈和关键数据。访问延迟较可预测 |
| 普通 SRAM、Flash、外部映射存储 | 地址经总线互连访问后级设备，部分区域可使用 L1 Cache | 实际路径取决于地址、访问类型、MPU 和 Cache 状态 |
| MMIO 寄存器 | 对映射地址执行指定宽度的访问，由设备逻辑响应 | 读写可能触发外设动作。位语义和访问宽度见 [MMIO 与 volatile](./MMIO与volatile.md) |

C 对象可以被优化成常量、驻留在通用寄存器或放入内存。对必须保留的访存，地址和属性决定数据路径。TCM 是可寻址的 RAM。L1 Cache 由硬件根据地址和属性自动管理，程序不会为它分配独立地址段。TCM 路径与 Cache 可并用，分别服务于固定区域和可缓存区域。实际周期数应在目标板上测量。

## STM32H743VIT6 片内存储

| 存储区域 | 起始地址 | 容量 | 数据访问路径 |
| --- | --- | ---: | --- |
| 内部 Flash | `0x08000000` | 2 MiB | Flash 接口，常放代码、只读数据和初始化镜像 |
| ITCM RAM | `0x00000000` | 64 KiB | ITCM 专用路径 |
| DTCM RAM | `0x20000000` | 128 KiB | DTCM 专用路径 |
| AXI SRAM（D1） | `0x24000000` | 512 KiB | 总线访问，可按内存属性使用 Cache |
| SRAM1（D2） | `0x30000000` | 128 KiB | 总线访问，可按内存属性使用 Cache |
| SRAM2（D2） | `0x30020000` | 128 KiB | 同上 |
| SRAM3（D2） | `0x30040000` | 32 KiB | 同上 |
| SRAM4（D3） | `0x38000000` | 64 KiB | 总线访问，可按内存属性使用 Cache |
| 备份 SRAM | `0x38800000` | 4 KiB | 位于备份域，保留行为取决于供电和域配置 |

这里的起始地址用于查找对应区域。工程中的变量落点由 [链接脚本与启动初始化](./链接脚本与启动初始化.md) 决定。不同 DMA 主设备的总线可达范围要单独确认。H743 的 DMA1/DMA2 无法直达 TCM，MDMA 具备专用 TCM 访问路径。具体 DMA 缓冲策略见 [Cache 与 DMA 一致性](./Cache与DMA一致性.md)。

## 外部 SDRAM 与 FMC

FMC 是芯片内的存储器控制器。SDRAM 初始化并映射后，CPU 的地址访问经总线送到 FMC，再由 FMC 产生外部器件所需的命令、地址、时序与刷新。设计板卡时按 **STM32H743VIT6 的具体封装**核对数据线、地址线、时钟和控制信号是否引出。系列支持 FMC 只说明控制器存在，板上实际能接哪种存储器还取决于可用引脚和布线。

## 网关内存怎么选

| 数据用途 | 优先评估 |
| --- | --- |
| 高频 CPU 私有状态、关键栈 | DTCM，确认容量与访问者 |
| 较大的协议处理缓冲区 | AXI SRAM，结合带宽和 Cache 属性 |
| DMA 收发缓冲区 | 该 DMA 可达的 SRAM，再确定一致性方案 |
| FDCAN 接收 FIFO 和发送缓冲区 | [FDCAN Message RAM](../外设通信/FDCAN网关/消息存储与收发中断.md#ram)，按外设配置划分 |
| 大容量帧缓存 | AXI SRAM 或板级条件允许的外部 SDRAM，实测带宽 |
