# STM32H743 独立看门狗配置与喂狗

下面这组 IWDG1 配置表示：LSI 经 32 分频驱动递减计数器，每次有效喂狗将计数器重装为 4000，关闭过早喂狗的窗口限制。按 LSI 标称 32 kHz 计算，不再喂狗时约 4 秒后触发复位。

```c
hiwdg1.Init.Prescaler = IWDG_PRESCALER_32;
hiwdg1.Init.Window = 4095;
hiwdg1.Init.Reload = 4000;
```

## 三个参数分别控制什么 {#parameters}

| 配置 | 对应硬件 | 作用 |
| --- | --- | --- |
| `Prescaler = IWDG_PRESCALER_32` | `IWDG_PR` 预分频寄存器 | 将 LSI 时钟除以 32，决定递减一步所需的时间 |
| `Reload = 4000` | `IWDG_RLR` 重装载寄存器 | 保存重装值；有效喂狗后，当前计数器从 4000 重新递减 |
| `Window = 4095` | `IWDG_WINR` 窗口寄存器 | 设为 12 位最大值 `0xFFF`，关闭过早喂狗限制；超时复位功能仍然有效 |

`IWDG_PRESCALER_32` 是 HAL 的寄存器编码宏，在 H743 中编码为 `0b011`，代表硬件除以 32。编程时使用该宏，计算时间时使用除数 32。`Reload` 与 `Window` 均为 12 位数值，范围为 0～4095。 [ST H7 HAL · IWDG 类型与宏](https://github.com/STMicroelectronics/stm32h7xx-hal-driver/blob/master/Inc/stm32h7xx_hal_iwdg.h)

## 超时时间怎样计算 {#timeout}

IWDG 使用独立低速内部 RC 时钟 LSI，不随 CPU 主频或 APB 分频直接改变。H743 的 LSI 标称为 32 kHz；时间计算需要使用实际 LSI 频率，不能套用 LSE 的 32.768 kHz。 [ST · STM32H743 数据手册，LSI oscillator characteristics](https://www.st.com/resource/en/datasheet/stm32h743xi.pdf)

用于估算计数周期与不喂狗超时的公式为：

```text
f_count   = f_LSI / P
T_tick    = P / f_LSI
T_timeout ≈ (R + 1) × P / f_LSI
```

- `f_LSI`：实际 LSI 频率，单位 Hz。
- `P`：预分频除数，此处为 32。
- `R`：重装值，此处为 4000。
- `f_count`：递减计数频率，单位 Hz；`T_tick` 为一次计数周期，单位秒。
- `T_timeout`：从一次有效重装载起、不再喂狗时的超时估算，单位秒。`R + 1` 对应包含 0 在内的计数周期数。

代入标称频率，独立计算得到：

```text
f_count   = 32000 / 32 = 1000 Hz
T_tick    = 32 / 32000 = 0.001 s = 1 ms
T_timeout ≈ (4000 + 1) × 32 / 32000 = 4.001 s
```

因此可以把该配置理解为**约 4 秒看门狗**。LSI 存在频率偏差，4.001 秒是标称计数估算，不能当作板上精确保证时间。设计喂狗间隔时应按适用器件与工作条件下的最快 LSI 计算最短超时，并留出任务调度和执行时间余量。 [ST H7 HAL · IWDG 时钟与超时说明](https://github.com/STMicroelectronics/stm32h7xx-hal-driver/blob/master/Src/stm32h7xx_hal_iwdg.c)

由公式可见，预分频除数加倍会让计数变慢、超时时间加倍；例如改为 64 分频，其他参数不变时名义超时约为 8.002 秒。保持 32 分频，把 `Reload` 改为 2000，名义超时约为 2.001 秒。`Window` 不参与超时时间公式，它单独限制提前喂狗的时机。

## 配置与喂狗如何作用到计数器 {#reload}

给 `hiwdg1.Init` 赋值首先只是在填写 RAM 中的配置结构。通常由 CubeMX 生成的 `MX_IWDG1_Init()` 调用 `HAL_IWDG_Init(&hiwdg1)`，将配置写入硬件、启动 IWDG，并在初始化结束前完成重装载。IWDG 启动后持续运行；这里的三个字段没有设置“自动喂狗周期”。

初始化示意如下。若工程已经生成 `MX_IWDG1_Init()`，在生成函数内核对参数即可：

```c
hiwdg1.Instance = IWDG1;
hiwdg1.Init.Prescaler = IWDG_PRESCALER_32;
hiwdg1.Init.Window = IWDG_WINDOW_DISABLE; /* 等价于 4095 */
hiwdg1.Init.Reload = 4000U;

if (HAL_IWDG_Init(&hiwdg1) != HAL_OK) {
    Error_Handler();
}
```

运行中调用：

```c
HAL_IWDG_Refresh(&hiwdg1); /* 向 IWDG_KR 写入 0xAAAA，触发重装载 */
```

喂狗将当前计数器恢复为 `IWDG_RLR` 保存的 4000，随后继续递减；不会把 4000 加到剩余计数，也不会装入窗口值 4095。只修改 `hiwdg1.Init.Reload` 并调用 `HAL_IWDG_Refresh()`，不会把新的结构体字段写入 `IWDG_RLR`。 [ST H7 HAL · HAL_IWDG_Init 与 HAL_IWDG_Refresh](https://github.com/STMicroelectronics/stm32h7xx-hal-driver/blob/master/Src/stm32h7xx_hal_iwdg.c)

## Window 如何限制喂狗时机 {#window}

设当前递减计数值为 `C`，窗口阈值为 `W`。在超时前，只有 `C ≤ W` 时执行重装载才满足窗口要求；`C > W` 时喂狗会触发复位。窗口检查的是**喂狗瞬间的当前计数值**。

当前配置 `R=4000`、`W=4095`，计数器重装后就满足 `4000 ≤ 4095`，之后的递减过程中也一直满足条件。因此可以在超时前任意时刻喂狗；4095 是关闭窗口限制的值，不能将它解释为 4095 ms 的等待时间。 [ST · RM0433，IWDG Window option](https://www.st.com/resource/en/reference_manual/rm0433-stm32h742-stm32h743753-and-stm32h750-value-line-advanced-armbased-32bit-mcus-stmicroelectronics.pdf)

保持 `P=32`、`R=4000`、LSI 按 32 kHz 估算，对比不同窗口设置：

| Window | 何时开始允许喂狗 | 过早喂狗的结果 |
| --- | --- | --- |
| `4095` | 重装后即可，窗口限制关闭 | 无过早喂狗复位 |
| `4000` | 重装后即可，因为当前值等于阈值 | 本配置下无过早喂狗复位 |
| `3000` | 从 4000 减到 3000 后，约等待 1 秒 | 当前计数仍大于 3000 时喂狗会复位 |

窗口开启等待时间的计数估算为：

```text
T_open ≈ max(R - W, 0) × P / f_LSI
```

其中 `W` 为窗口阈值，其他符号与超时公式相同，`max` 取两者较大值。该公式用于计算重装后至少要等待多久，才能进入允许喂狗的窗口。例如 `W=3000` 时：`(4000-3000) × 32/32000 = 1 s`。因此名义允许区间约为重装后 1 秒至 4 秒超时前，实际操作应避开边界。

## 喂狗与停止喂狗的时间示例 {#examples}

以下沿用原配置，所有时间均按标称 LSI 估算：

```text
0.0 s：初始化结束，计数器重装为 4000
1.0 s：执行一次喂狗，计数器恢复为 4000
2.0 s：再执行一次喂狗，计数器再次恢复为 4000
之后停止喂狗：约在 6.0 s 附近触发复位
```

每次有效喂狗都从该时刻重新获得约 4 秒的计数预算。若从初始化结束后一直不喂狗，则约在 4 秒后复位。若把 `Window` 改为 3000，重装后 0.5 秒就喂狗会因过早触发复位，即便尚未达到超时时间。

用于验证硬件超时的做法是：在固定位置喂狗并产生一个可观测标记，随后停止喂狗，用外部采集观察该标记到复位的间隔。启动时可检查 `RCC_FLAG_IWDG1RST` 追踪复位来源，并在保存信息后清除复位标志。 [ST · H743 IWDG 窗口示例](https://github.com/STMicroelectronics/STM32CubeH7/blob/master/Projects/STM32H743I-EVAL/Examples/IWDG/IWDG_WindowMode/Src/main.c)

断点测试时还应核对 `__HAL_DBGMCU_FREEZE_IWDG1()` 对应的调试冻结设置，否则 CPU 暂停期间 IWDG 可能继续计数。 [ST H7 HAL · IWDG 调试说明](https://github.com/STMicroelectronics/stm32h7xx-hal-driver/blob/master/Src/stm32h7xx_hal_iwdg.c)

在 FreeRTOS 工程中，喂狗应以关键任务完成进度或健康检查为条件。一个仍能定时运行的任务持续喂狗，会掩盖其他关键任务卡死的问题。任务进度与调度排查可结合[FreeRTOS 任务与内存排查](./FreeRTOS任务与内存排查.md)阅读。
